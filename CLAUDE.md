# CLAUDE.md

## Project Overview

**ShelfCtrl** gère une collection personnelle de BD, DVD et Blu-ray : inventaire, prêts, état et suivi des ventes. Multi-compte (chaque compte a sa collection, entièrement isolée), auto-hébergé sur un Synology DS723+, utilisé sur PC et sur Android (PWA).

- **Client** : React 19 + Vite, Tailwind CSS 4, TanStack Query, react-router v7+.
- **Server** : Node.js/TypeScript, Express 5, SQLite (`better-sqlite3`), Zod.
- **Shared** (`@shelfctrl/types`) : types et constantes partagés client/serveur.

Même stack et mêmes conventions que `cash-ctrl` (monorepo npm workspaces, CI GitHub Actions → ghcr.io → Watchtower).

## Development Commands

- `npm run dev` : serveur (`tsx watch`, port 3001) + client (Vite, port 5173, proxy `/api` et `/covers`).
- `npm run build`, `npm run lint`, `npm run format`.
- `npm run test` / `test:coverage` : Vitest (client et serveur).
- `npm run typecheck:test --workspace=client` : types des tests client (`tsconfig.json` exclut les `*.test.ts(x)`) ; `npm run typecheck --workspace=server` : types du serveur (tsup ne les vérifie pas).
- **Fichiers communs avec cash-ctrl** dans le dépôt [`jerem-gt/ctrl-shared`](https://github.com/jerem-gt/ctrl-shared) : workflow CI/Docker réutilisable (appelé par `.github/workflows/ci.yml`), `Dockerfile`, script `prepare-runtime-deps` (devDependency `@jerem-gt/ctrl-shared`, **même tag que le workflow**), preset Renovate et **code serveur commun** en sources TS (`import … from '@jerem-gt/ctrl-shared/server/<module>'`, embarqué par tsup) : `mailer`, `crypto` (`sha256Hex`), `setup` (jeton de premier démarrage), `rateLimit` (`FailureRateLimiter`), `session-store` (`SQLiteSessionStore`), `errors` (`createHttpErrors`, instanciée sur le registre du projet dans `lib/errors.ts`), `apiErrors` (codes de base, `createErrorRegistry`, `zodToApiError`), `errorHandler` (`createErrorHandler`), `migrations` (`runMigrations`) et les briques de la 2FA : `totp` (`newTotpSecret`, `matchTotpStep`), `trustedDevices` (repo), `deviceCookie` (`createDeviceCookies`), `cookies` (`readCookie`), `userAgent` (`deviceLabel`). Ne pas les recopier ici : un changement se fait dans `ctrl-shared`, puis un nouveau tag que Renovate propose de monter dans les deux projets. Propre à shelf-ctrl : `.github/smoke.env` (variables du conteneur) et `.github/smoke-test.sh` (login, `sharp`). L'image n'est construite que si une release est publiée (push sur `main` ou `develop` avec un commit `feat`/`fix`) ; les checks s'appellent `app / 🧪 CI & Tests`, etc.
- Hook pre-commit : Husky + lint-staged (ESLint + Prettier sur les fichiers stagés).

## Modèle de données

Titre → édition → exemplaire :

- `works` : l'œuvre (titre, série, numéro de tome).
- `editions` : une version d'une œuvre (format `book`/`dvd`/`bluray`/`uhd4k`, code-barres ISBN/EAN, éditeur, pochette).
- `copies` : **l'objet physique possédé** (état sur 5 niveaux, note, photo, emplacement).
- `borrowers`, `loans`, `sales` : mouvements d'un exemplaire.
- **Tout est par compte** : `user_id` (cascade à la suppression du compte) sur works, editions, copies, borrowers, loans, sales et platforms (migration 2) ; les unicités le sont aussi (code-barres, emprunteur, plateforme, plateforme par défaut). Chaque service reçoit le compte de la requête (`currentUserId(res)`, posé par `requireAuth`) et filtre toutes ses requêtes dessus ; un objet d'un autre compte répond **404**. `server/src/isolation.test.ts` le vérifie module par module : toute route ajoutée s'y teste.
- **Le statut d'un exemplaire (`owned`/`loaned`/`listed`/`sold`) n'est jamais stocké** : il dérive des mouvements via la vue `copy_status`. Ne jamais ajouter de colonne `status` sur `copies`.
- **Ventes** : au plus une ligne `sales` par exemplaire (index unique). La ligne seule vaut « en vente » (`listed_at`), `sold_at` renseigné vaut « vendu » (vente directe : `listed_at` nul). Retirer l'annonce ou annuler la vente supprime la ligne ; un exemplaire prêté ne peut pas être vendu. Prix en centimes.
- **Prêts** : un seul prêt en cours par exemplaire (index partiel) ; un exemplaire vendu ne peut plus être prêté. Dates au format AAAA-MM-JJ, par défaut le jour même.
- États, formats et statuts sont définis une seule fois dans `shared/src/index.ts` ; les `CHECK` SQL de `server/src/db/schema.ts` doivent rester alignés.

## TypeScript & Code Quality

- **Strict Mode** : jamais `any`, préférer `unknown`.
- **Path Aliases** : `@/*` pour les imports dans `src/`.
- Interdiction des variables/paramètres inutilisés et des fallthrough dans les switchs.
- **Target** : client ES2023 / serveur ES2025.
- **Ternaires imbriqués** (Sonar) : interdits ; extraire dans une variable `let` avec `if/else` ou une fonction nommée.
- **Conditions négatives** (Sonar) : mettre la branche positive en premier dans un `if/else`.

## Architecture

### Frontend

- État asynchrone : TanStack Query uniquement. Icônes : `lucide-react`.
- **Mobile-first** : toute interface doit être affichable sur mobile (breakpoints `md:`, `lg:`), pas de largeurs fixes.
- Le scan de code-barres utilise la caméra (`BarcodeDetector`, supporté par Chrome Android) ; HTTPS requis.

### i18n

Français uniquement pour l'instant, mais **tous les textes passent par `useTranslation`** (`client/src/locales/fr/`). Pour ajouter l'anglais : créer `locales/en/` en miroir exact des clés `fr/`.

### Backend

- **Documentation de l'API** (module `openapi`, comme cash-ctrl) : Swagger UI sur `/api/docs`, spec sur `/api/docs/openapi.json`, publique (aucune donnée). Spec écrite dans `server/src/openapi/spec.ts`, corps et paramètres générés depuis les schémas Zod des routes : toute route ajoutée ou modifiée s'y reporte.
- Séparer routes, services et validation (Zod). **Migrations SQLite par `user_version`** (`server/src/db/migrations.ts`) : `schema.ts` crée le schéma initial (idempotent), puis chaque migration de la liste s'applique dans l'ordre et incrémente la version (runner `runMigrations` de ctrl-shared : une transaction par migration, clés étrangères coupées puis contrôlées) ; ne jamais modifier une migration livrée, en ajouter une.
- Les images (pochettes, photos) sont stockées dans `DATA_DIR` et servies par le serveur, jamais liées à distance. Module `images` : tout est converti en WebP par `sharp` (réduit à 900 px pour les pochettes, 1600 px pour les photos, EXIF retiré) dans `DATA_DIR/images/{covers,photos}` ; le nom `<id>-<empreinte>.webp` rend le cache immuable (`/covers/*`, `/photos/*`, derrière la session, et servis au seul compte propriétaire, 404 sinon). Supprimer un compte efface ses fichiers d'images. La pochette appartient à l'**édition** (`editions.cover_path`, partagée par ses exemplaires, supprimée avec la dernière), la photo à l'**exemplaire** (`copies.photo_path`). Envoi en corps brut (`PUT /api/editions/:id/cover`, `PUT /api/copies/:id/photo`, 12 Mo max). À l'ajout d'un exemplaire sans pochette, elle est cherchée en arrière-plan (Open Library par ISBN ; TMDB par titre et année si `TMDB_API_KEY`) ; `POST /api/editions/:id/cover/fetch` relance la recherche et remplace.
- **Annonces** : un simple **gabarit**, calculé côté client (`client/src/lib/listing.ts`, textes dans `locales/fr` sous `listing`), sans serveur ni IA. Titre ajusté à la limite de la plateforme (`lib/platforms.ts` : Vinted 60, Leboncoin 70, eBay 80, 80 par défaut) ; description faite des champs renseignés, sans prix suggéré (aucune donnée de marché fiable). L'annonce est **fusionnée avec la mise en vente** : le formulaire « Mettre en vente » (plateforme obligatoire) et celui de modification affichent l'annonce en direct pour la plateforme saisie ; une annonce déjà publiée se rouvre depuis la fiche. « Marquer comme vendu » garde la plateforme facultative (« vendu sur… »). Un LLM distant avait été essayé (Gemini/Groq/Mistral) puis retiré : gain marginal face à un gabarit, pannes et quotas des offres gratuites, dépendance et clé à gérer.
- **Import CSV** (module `import`, page `/import`) : fichier envoyé en corps brut (2 Mo, 1000 lignes max), décodé en UTF-8 puis Windows-1252, séparateur détecté (`;` `,` tabulation), colonnes reconnues par leur en-tête (FR/EN, accents et ordre indifférents : titre, série, tome, auteurs, format, code-barres, éditeur, année, langue, état, note, emplacement ; les autres sont ignorées). `GET /api/import/template` donne un modèle (BOM + `;`, pour Excel). `POST /api/import/preview` contrôle sans rien écrire ; `POST /api/import` lance une **tâche de fond en mémoire** (un seul import à la fois par compte, 409 sinon ; perdue au redémarrage) suivie par `GET /api/import/:id` (tâches du seul compte), car une complétion en ligne dépasse le délai du reverse proxy. Une ligne avec code-barres mais sans titre, auteurs ou éditeur (ou un EAN vidéo sans support) est **complétée en ligne** comme au scan : les valeurs du fichier priment, un code introuvable sans titre est une erreur de ligne. Format absent → livre si ISBN ou sans code, sinon fiche en ligne. Les doublons créent **un exemplaire de plus** (l'aperçu les signale). La pochette de chaque nouvelle édition est cherchée ensuite. Erreurs par ligne (codes, traduits côté client), sans bloquer les autres.
- **Réglages du compte** (module `platforms`, page `/settings`) : carte « Mon compte » (profil, mot de passe, voir Authentification), puis les plateformes de vente où l'on a un compte (table `platforms`, migration 1) et celle **par défaut** (au plus une, index unique ; la première ajoutée l'est d'office). Plateformes connues (Vinted, Leboncoin, eBay, Momox, Rakuten, Amazon : adresse de dépôt et limite de titre dans `client/src/lib/platforms.ts`, rien de figé en base) à cocher, ou **personnalisées** avec une adresse de dépôt facultative (http/https seulement : elle devient un lien). Le formulaire de mise en vente propose ces plateformes, la plateforme par défaut présélectionnée ; sans aucun réglage, toutes les plateformes connues sont proposées. Les ventes gardent le nom en clair : retirer une plateforme ne touche pas à l'historique, et celle d'une annonce existante reste proposée à la modification.
- **Authentification et comptes** (portage de la refonte de `cash-ctrl`, à garder iso) : `express-session` avec un store SQLite (`SQLiteSessionStore` de ctrl-shared, qui sait fermer les sessions d'un compte), mot de passe haché en `bcrypt` (coût 12), régénération de la session à la connexion, échecs limités (`FailureRateLimiter`, persisté en base : par IP pour la connexion, par compte pour le mot de passe actuel). Les comptes sont **en base** (aucune variable d'environnement : `ADMIN_USER`/`ADMIN_PASSWORD` sont obsolètes, signalées et ignorées).
  - **Premier démarrage** : sans compte, un jeton à usage unique est écrit dans les logs (`setup token: …`) ; `GET/POST /api/auth/setup` crée le premier compte, admin (page `SetupPage`). Le smoke test CI lit ce jeton dans `docker logs`.
  - **Admin = rôle** (`users.is_admin`, relu en base à chaque requête) : page Utilisateurs `/admin` (`/api/users` : créer, modifier nom/e-mail/mot de passe/rôle, supprimer avec sa collection), e-mail de test. Garde-fous : dernier admin, pas d'auto-suppression ; redéfinir le mot de passe d'un compte ferme ses sessions.
  - **Profil** (`PATCH /api/auth/profile`, mot de passe actuel requis) : nom et e-mail facultatif, unique, normalisé ; `POST /api/auth/change-password` ferme les autres sessions.
  - **Mot de passe oublié** (`/api/auth/password/forgot|reset`, pages `/forgot-password`, `/reset-password`) : par nom ou e-mail, réponse identique ; jeton 30 min, seule son empreinte SHA-256 est stockée, vérifié avant le bcrypt puis dans la transaction, à usage unique ; ferme toutes les sessions. Lien par SMTP (nodemailer, `mailer` de ctrl-shared, textes dans `lib/mailTexts.ts`, `APP_URL`), sinon écrit dans les logs.
  - Tout `/api` exige une session sauf `/api/health`, `/api/docs` et `/api/auth/*` (hors profil, mot de passe et e-mail de test). En production, le serveur **refuse de démarrer** si `SESSION_SECRET` (32 caractères minimum) manque ou est vide : un compose dont la variable est absente la passe à vide. Le cookie s'appelle `shelfctrl.sid` (cookies et noms d'hôte sont partagés avec `cash-ctrl` sur le NAS) et est `Secure` derrière HTTPS (`SECURE_COOKIE=true` + `trust proxy`). Sans `auth` (tests de modules), `createApp` agit pour le compte `actAsUserId` (1 par défaut, `createTestDbWithUser`).
  - **2FA (TOTP, iso cash-ctrl)** : `users.totp_secret`, `totp_enabled`, `totp_last_step` (migration 3), `otpauth` (SHA1, 6 chiffres, 30 s, ±1 période, module `totp` de ctrl-shared). Connexion en deux temps : mot de passe juste et 2FA active → `{ totpRequired: true }`, session en attente 5 min, puis `POST /api/auth/2fa/verify { code, remember }`, limité par IP **et** par compte (`totp:<id>`). **Anti-rejeu** : le pas accepté est mémorisé (`UPDATE` conditionnel), un code ne sert qu'une fois, celui de l'activation compris. Activation : `/2fa/setup` garde le secret **en session** (`pendingTotpSecret`), `/2fa/enable` ne reçoit que `{ code }` ; désactivation avec le mot de passe actuel ; un admin la désactive par `DELETE /api/users/:id/2fa` (téléphone perdu). Pas de codes de secours.
  - **Appareils mémorisés** (« se souvenir 30 jours », `trusted_devices`, modules `trustedDevices` et `deviceCookie` de ctrl-shared) : cookie `shelfctrl_device` (HttpOnly, SameSite=Strict, Path=`/api/auth`, Secure comme la session), seule l'empreinte SHA-256 est stockée ; un cookie mort est effacé, celui d'un autre compte gardé. Révoqués à tout changement de mot de passe (changement, oubli, admin) et à l'activation ou désactivation de la 2FA ; le mot de passe oublié ne touche pas à la 2FA. `GET/DELETE /api/auth/devices[/:id]`, carte « Double authentification » de `/settings`.
- **Erreurs** (iso cash-ctrl) : corps `{ error: { code, message, params?, fields? } }`. Codes namespacés (`copy.not_found`, `loan.already_loaned`…) et message FR de repli dans le registre unique `server/src/lib/errorCodes.ts`, qui étend les codes de base de ctrl-shared (`common.*`, `validation.*`) et en tire `renderMessage`, `buildError`, `sendError` (`createErrorRegistry`) : tout nouveau code métier s'y ajoute, et sa traduction dans `client/src/locales/fr/errors.json` (namespace i18n `errors`). Services et routes **lèvent** des `HttpError` (`lib/errors.ts` : `NotFoundError`, `ConflictError`, `BadRequestError`, ou `HttpError(status, code)`) ; le gestionnaire global (`createErrorHandler` de ctrl-shared, monté dans `app.ts`) les traduit, convertit les erreurs Zod (`schema.parse`) en `validation.invalid` avec le détail par champ, celles des lecteurs de corps (413, JSON illisible) et répond 500 `common.internal` au reste ; 4xx journalisées en avertissement (muettes en test), 500 avec leur pile. Une erreur levée dans un `db.transaction` l'annule. Le client (`api/client.ts`) traduit le code (ou chaque champ), sinon garde le message du serveur ; `ApiError` expose `status`, `code` et `body`. Tests client : `apiError(code, status)` (`tests/msw/apiError.ts`). Les problèmes par ligne de l'import CSV ne sont pas des erreurs d'API (traduits sous `import.issues`).
- Résolution des codes-barres (`GET /api/barcodes/:code`, module `barcodes`) : le code est normalisé (ISBN-10 → ISBN-13, UPC-A → EAN-13, clé de contrôle vérifiée), cherché d'abord dans la collection, puis dans une chaîne de sources par type de code, avec repli en saisie manuelle (404). ISBN : BnF (SRU, gratuit, série et tome des BD francophones ; cherche l'ISBN-13 et l'ISBN-10, les anciennes notices n'ont que le second), puis Google Books (si `GOOGLE_BOOKS_API_KEY`, le quota anonyme est nul), puis Open Library. EAN vidéo : UPCitemdb (gratuit, limité en débit), dont le titre est fiabilisé par TMDB si `TMDB_API_KEY` (TMDB ne cherche pas par code-barres). Une source en erreur est ignorée ; les codes sont stockés sous leur forme normalisée.
- Recherche par titre (`GET /api/titles/search?q=`, module `titles`, formulaire d'ajout) : sans code-barres, ou code inconnu. Sources interrogées en parallèle, une en erreur est ignorée, doublons de code-barres retirés, jamais de 404 (liste vide). Livres : BnF (SRU, textes imprimés) puis Open Library ; films : TMDB si `TMDB_API_KEY` (titre et année seulement, sans code-barres ni support). Le résultat choisi préremplit le formulaire, une valeur absente laisse la saisie en place.

## Déploiement

Stack Portainer dédiée, qui lit `docker-compose.yml` tel quel sur la branche `develop` de GitHub, redéployée à la main (Watchtower ne met à jour que les images) : une variable ajoutée au compose se crée d'abord dans la stack Portainer, sinon elle arrive vide ; prod sur le port 3101, dev sur 4101 (identiques en interne et publiés, comme cash-ctrl ; 3001 et 4001 étaient déjà utilisés sur le NAS), données dans `/volume1/data/shelf-ctrl` et `/volume1/data/shelf-ctrl-dev`. Image `ghcr.io/jerem-gt/shelf-ctrl` construite par la CI, mise à jour automatiquement par Watchtower (scope `app-fast`). Image allégée : serveur entièrement bundlé par tsup (`server/tsup.config.ts`) hors modules natifs listés dans `server/runtime-externals.json` (better-sqlite3, bcrypt, sharp, swagger-ui-express), dont `prepare-runtime-deps` (`ctrl-shared`) extrait les seuls binaires linux/x64/musl dans `deploy/node_modules` (à lancer sur Alpine : npm n'installe que les `@img/sharp-*` de l'hôte) ; seul le fuseau Europe/Paris est embarqué ; la CI démarre l'image (santé, front, docs, puis `.github/smoke-test.sh`) avant le push. Un nouveau module natif s'ajoute à `runtime-externals.json` (et, s'il a des prebuilds par plateforme, leur filtrage au script de `ctrl-shared`). Variables : `SESSION_SECRET` (prod) et `SESSION_SECRET_DEV` (dev, distinct : les cookies ne sont pas isolés par port), `PUID`, `PGID` ; facultatives (vides par défaut) : `GOOGLE_BOOKS_API_KEY`, `TMDB_API_KEY`, et pour les e-mails « mot de passe oublié » `APP_URL` / `APP_URL_DEV`, `SMTP_HOST`, `SMTP_PORT` (587 si vide), `SMTP_USER` (aussi expéditeur), `SMTP_PASS` ; le `mailer` de ctrl-shared lit aussi `SMTP_FROM` (expéditeur distinct de `SMTP_USER`) et `SMTP_SECURE` (TLS direct, par défaut sur le port 465), absentes du compose car inutiles avec Gmail.
